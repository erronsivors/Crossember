## 2026-11-19 — Триггеры в редакторе алерта, правило без действий не перехватывает (Claude)
Нашли с пользователем: донат DA («Добавить вручную») пришёл в Crossember, но показался алерт из общего правила «Донат», а не настроенный шаблон — алерт показывают правила, а новый шаблон ни к одному не привязан. После удаления стандартного шаблона у правила «Донат» не осталось действий, но оно, включённое и с «остановить проверку», перехватывало донаты — новых алертов не было вовсе.
Решили: правило без действий пропускается и не останавливает следующие (`rules.ts process`). В редакторе, в «Весь алерт», — блок «Когда запускается» (как в Stream Tools): триггер = событие + площадки + сумма от; это правило с действием «этот алерт», новое ставится первым (`rulePut(r, first)`), чтобы общее правило его не перехватило. В верхней панели редактора кнопка «Когда запускается: N» / «Не запускается — добавьте триггер». Пункт 4б фидбека закрыт этим.
Проверено: typecheck, сборка. Вживую не проверено.
База пользователя проверена при закрытом Crossember: повреждена по-настоящему (индексы settings/secrets указывают на чужие строки, viewers/streams не читаются; ни один снимок «основной файл + WAL до коммита N» не цел). Собрана новая база: settings и templates.v1 — из последнего состояния, rules.v1, counters.v1, server.*Key — из основного файла (правила перепривязаны к текущим шаблонам по имени), секреты YouTube, Twitch-стример, DonationAlerts, пароль OBS, 28 событий. Потеряны входы GoodGame, VK, Kick, Boosty, бот Twitch и свежие правки правил. Старые файлы — `data/broken-2026-11-19/`. Причина повреждения неизвестна. Дополнительно: правило, у которого все алерты ссылаются на удалённые шаблоны, тоже пропускается.
Сделано следом: при запуске `PRAGMA quick_check` (`core/db.ts`); база не цела — файлы в `data/broken-<время>/`, новая база, в неё всё читаемое: settings/secrets полным проходом и по индексу с проверкой, что ключ строки совпал (иначе индекс отдаёт чужую строку), события, таблицы аналитики; окно с итогом и запись в журнал программы. Проверено на копии повреждённой базы пользователя: 5 настроек, 4 входа, 28 событий, новая база цела; целая база не трогается. Вживую в приложении не проверено.

## 2026-11-19 — GoodGame: вход и запись в чат; VK — вход без секрета (Claude, ревью Codex)
Решили: пересмотрели вывод «GoodGame нельзя»: пользователь показал, что Stream Tools входит через goodgame.ru/oauth2/authorize с возвратом на localhost. Адреса входа и обмена кода (POST goodgame.ru/oauth2/token, секрет в теле) описаны только в неофициальном gist strayge «goodgame.ru_api4.md»; сервер настоящий (на чужой ключ отвечает invalid_client). Смена названия — POST `/api/4/streams/for-helpers/game-title` из официального описания api4 (swagger), игра по поиску `/api/4/games/autocomplete/games`, без игры оставляем текущую. Чат — официальный протокол chat2: `auth {user_id, token}` перед `join`, потом `send_message`; токен чата — из `/api/4/user`. При входе/выходе GoodGame чат переподключается.
VK «в один клик»: VK запрещает держать секрет приложения у клиента, поэтому для общего приложения Crossember вход без секрета (ImplicitFlow из документации DevAPI: токен сразу, без обновления; страница-мост на localhost переносит токен из «#» в запрос). Со своим секретом — по-прежнему CodeFlow. Stream Tools ведёт события VK через свой сервер; у нас сервера нет, чтение чата VK остаётся как было.
«Подключения»: если общего приложения нет, настройка своего показана сразу: 3 шага, «Открыть сайт», «Копировать» адрес возврата, поля Client ID (+ секрет, для VK не нужен). Адрес возврата GoodGame: страница `https://erronsivors.github.io/Crossember/gg-callback.html` (файл `docs/gg-callback.html`, GitHub Pages с main/docs) — GoodGame запрещает в приложениях «localhost», «127.*» и goodgame.ru (проверил пользователь 19.11). Страница сразу переносит code и state на `http://127.0.0.1:47837/callback`; секретов на ней нет. Путь чувствителен к регистру: `/Crossember/`, не `/crossember/`. Client ID у GoodGame — «уникальное название» приложения, сайт выдаёт только секрет.
Ревью Codex (5 замечаний), исправлены все: токен со страницы-моста уходит POST-запросом, адрес с ним стирается из истории; «Отмена» входа не даёт завершившемуся обмену сохранить вход; чат GoodGame переподключается и при повторном входе в тот же аккаунт; старый ответ о канале GoodGame не перезаписывает новый; смена названия GoodGame отменяется, если вход или ник сменились по ходу.

## 2026-11-19 — Kick и VK Видео Live: сообщения в чат и смена названия; GoodGame — нельзя (Claude, ревью Codex)
Решили: по официальной документации. Kick (docs.kick.com): отправка `POST /public/v1/chat` с правом `chat:write`, ответ в ветку по `reply_to_message_id`; название уже менялось. Старый вход Kick без `chat:write` — показываем «войдите заново». VK Видео Live (dev.live.vkvideo.ru/docs): вход CodeFlow, права `chat:message:send` и `channel:stream:settings`, отправка `POST /v1/chat/message/send` (нужен id текущей трансляции, поэтому писать можно только в эфире), название и категория `POST /v1/channel/stream/edit`, поиск категорий `/v1/category/search`. VK без входа — по-прежнему «вручную». GoodGame (github.com/GoodGame/API): протокол `send_message` описан, но получение токена чата через OAuth (`chat.token`) и авторизация метода смены названия api4 — нет; не гадаем, оставили только чтение и «вручную» с честной подсказкой в «Подключениях».
Общий вход вынесен в `oauthlocal.ts` (возврат на localhost, state, PKCE для Kick); у Kick и VK можно указать своё приложение (Client ID + секрет в зашифрованном хранилище) или вшить общее при сборке, как у YouTube. Адреса возврата: Kick `http://localhost:47835/callback`, VK `http://localhost:47836/callback`.
Ревью Codex (8 замечаний), исправлено 7: вход/выход/смена приложения больше не перебивают друг друга (счётчик попыток), одно обновление токена на всех, одноразовый приём кода на localhost, вход не начинается, если порт занят другой программой, кэш трансляции VK сбрасывается при смене входа, профиль Kick переспрашивается перед отправкой, отправка запрещена, если вход в другой канал, чем указан в «Подключениях».
